# GSD Patterns Adopted by Terrace

## pattern_01: file-as-message-bus
source: gsd-tools.cjs, workflows/*.md
adoption: All Terrace state writes go through terrace-tools.cjs to .terrace/ files. No agent writes state directly.
departure: Terrace adds isAllowedWritePath() enforcement; GSD has no explicit path guard.

## pattern_02: workflow-as-orchestrator
source: workflows/*.md dispatch pattern
adoption: Terrace workflows chain step files sequentially, each naming the next.
departure: Terrace adds tri-modal structure (Create/Edit/Validate) in Phase 2.

## pattern_03: CLI-as-structured-write-path
source: gsd-tools.cjs output() and error() functions
adoption: terrace-tools.cjs uses identical output(data, jsonMode) and error(msg) signatures. All stdout goes through output(). --json flag controls serialization mode.
departure: Terrace wraps every write in isAllowedWritePath() guard.

## pattern_04: subagent-isolation
source: ~/.claude/agents/*.md agent definitions
adoption: Terrace agents follow the same YAML frontmatter format: name, description, tools, context. Each agent loads steering.md as its first context item.
departure: Terrace adds fragment-index.json for tiered knowledge loading (Phase 2).

## pattern_05: template-as-file-contract
source: gsd-tools.cjs templates/ directory
adoption: Terrace governance artifact templates are the file contracts. Agents and workflows expect exact YAML frontmatter fields. Templates are machine-precision per D-01.
departure: Terrace templates carry JSON Schema validation (src/schemas/) for programmatic enforcement.

## modification_policy

may_modify:
  - .terrace/ (all files — Terrace-owned)
  - docs/prd/, docs/spec/, docs/testing/ (Terrace-owned governance dirs)
  - .git/hooks/pre-commit (Phase 3 only; safe merge required; Terrace marker added)

may_read:
  - Any file in target repo (validation, spec hash computation)
  - .planning/ (read-only; never write — GSD-owned)
  - ~/.claude/ (read-only; never write — GSD-owned)

will_never_modify:
  - .planning/ (GSD-owned; D-06 absolute constraint)
  - ~/.claude/ (GSD-owned; D-06 absolute constraint)
  - package.json (user-owned project file; not a governance artifact)
  - node_modules/ (npm-managed; Terrace installs no production dependencies)

gsd_file_patch_policy:
  # GSD-02: every GSD-file modification recorded in decision log or install output
  # GSD-03: Terrace changes marked with terrace-managed comment block
  # GSD-04: interrupted init leaves no broken GSD state (writes atomic; .terrace/ only)
  # GSD-05: GSD installations remain operable after Terrace install
  # GSD-06: re-running terrace init against already-modified repo is idempotent
  # GSD-07: if a GSD file cannot be safely patched, exit non-zero with exact path and remediation
  phase_1_scope: Terrace Phase 1 does not modify any GSD files.
  future_phases: Hook installation (Phase 3) adds pre-commit hook with safe merge.
  failure_behavior: If a GSD file cannot be patched safely, exit 1 with exact file path and manual remediation instructions.

version: "1.0"
artifact: SECURITY-MODEL

last_updated: "2026-04-06"

# Terrace Security Model

## trust_boundaries
# Terrace operates entirely within the target repo and the user's local filesystem.
# No network calls. No external service dependencies. No user data transmitted externally (SEC-02).

## allowed_writes
# These are the ONLY paths Terrace may write to (SEC-01, SEC-06):
- pattern: "{repo}/.terrace/**"
  owner: terrace
  transparent: true
- pattern: "{repo}/docs/prd/**"
  owner: terrace
  transparent: true
- pattern: "{repo}/docs/spec/**"
  owner: terrace
  transparent: true
- pattern: "{repo}/docs/testing/**"
  owner: terrace
  transparent: true
- pattern: "{repo}/.git/hooks/pre-commit"
  owner: terrace
  transparent: true
  phase: 3
  condition: safe_merge_only

## allowed_reads
# Terrace may read any file in the target repo for validation and spec hash computation.
# Reads are non-destructive and produce no side effects.
- pattern: "{repo}/**"
  purpose: validation, spec_hash, artifact_check

## forbidden_modifications
# Terrace will never write to these paths (SEC-01, D-06):
- pattern: "{repo}/.planning/**"
  reason: GSD-owned; D-06 absolute constraint
- pattern: "~/.claude/**"
  reason: GSD-owned; D-06 absolute constraint
- pattern: "{repo}/package.json"
  reason: user project file; not a governance artifact
- pattern: "{repo}/node_modules/**"
  reason: npm-managed; Terrace does not install production dependencies

## hook_conflict_detection
# OPS-12: if pre-commit hook already exists, Terrace merges safely (Phase 3).
# Detection: if .git/hooks/pre-commit exists and does not contain the Terrace marker,
#            report HOOK_CONFLICT warning in terrace doctor output.
# Marker: terrace-hook-v1
# Resolution: terrace doctor prints exact manual merge instructions.

## code_execution_policy
# SEC-03: Terrace does not run arbitrary project code during install.
# Permitted: fs.readFileSync, fs.mkdirSync, fs.writeFileSync.
# Forbidden: child_process spawn/execFile on user project scripts, npm run, make, etc.

## policy_mode_transparency
# SEC-05: policy modes cannot silently disable critical protections.
# SEC-07: lightweight mode must state which protections are weakened.
#
# strict: all gates active
# standard: blocking gates active; some freshness warnings downgraded
# lightweight: blocking gates active for protected files only;
#              freshness warnings suppressed;
#              WARNING: spec_hash drift may not be surfaced

## audit_trail
# SEC-04, SEC-06: all file mutations during install/migrate printed to stdout as manifest.
# Format: { file: string, action: 'created' | 'skipped' | 'overwritten' }
# --json flag: machine-readable JSON array of all manifest entries.

## uninstall_path
# INST-07: to disable Terrace, remove .terrace/ and docs/prd|spec|testing/ directories.
# The pre-commit hook (Phase 3) must be manually removed from .git/hooks/pre-commit.
# No other files in the repo are owned by Terrace.
